2.Towards Efficient 3D Object Detection in Bird's-Eye-View Space for Autonomous Driving: A Convolutional-Only Approach

- 点评： 2023年12月1日挂出来的paper，作者来自新加坡南洋理工大学和德赛西威汽车电子新加坡。首先还是比较肯定这个工作虽然他并没有开源，但是一个好的方向。为什么这么说，因为在bev中他又快又准，并且全部使用卷积网络，这对于工业落地来说实在是太友好了，这也可能是没开源的一个原因。

从BEVENet整个网络架构来说，这个流程很清晰简洁。整个BEVENet 架构包括六个模块：

1. 在NuImage 预训练过的共享主干模型 ElanNet；

2. 具有查找表的视图投影模块 LSS；

3. 具有数据增强的全卷积深度估计模块；

4. 具有 2 秒历史信息的时间模块

5. 带有残差块的 BEV 特征编码器；

6. 圆形 NMS（Circular NMS）的简化检测头。

这里简单说一下各个模块的重点，Backbone是做了一些实验挑出来的包括了VIT，SwinT,Resnet和ElanNet；LSS在从 2D到3D 投影矩阵不涉及任何可学习的参数所以建查找表来加速，这也是前人有做过的；深度估计这部分从Bevdepth那里学来的，做了一些改变将增强矩阵和外参内参一起作为深度估计网络的输入。MLP层也换成了卷积。时间模块通过卷积编码器处理前一帧积累的特征映射，利用前两秒跨度的特征更好地解释遮挡物体的运动和定位。残差与NMS没什么好说的，Circular NMS用的Centerpoint。但也有比较有趣的地方，那就是用到re-parameterize。

对于re-parameterize我其实也不太熟，因为也不是专门做卷积的卷积有很多可以加速的方法而且也硬件友好，对transformer-based的方法会熟一点。所以看到了就应该学一下。

OK，然后backbone就不说了，area-to-area fusion也不说了就是pillar voxels级别加一些投影采样和划分规则。重点是（b）部分，f bev s1代表来自S1域的bev特征，其中Density-maintained Vector Modeling (DVM)用来生成充分体现域属性的全局向量，或者说将BEV特征映射转换为保持密度感知的全局向量。这是他们提出的一个概念。

Density Transfer (DT)，为了形成BEV向量的负对和正对，使用密度转移(DT)来生成另一个源域的近似BEV向量。具体地说，将当前批次中的点云密度转换为来自其他源域的点云密度，这个在图中最右侧部分。在这个过程中，点云的语义内容及其对应的图像保持不变。

使用这些合成点云及其对应的图像，可以生成一批密度转移的BEV向量，它们共享相同的语义内容，但感知另一个域的密度。这里注意(b)模块的左侧是f bev s1 右侧是f bev s1->s2，s1,s2就代表了不同的域。

再然后就是图中的Push和pull是怎么理解？

大家注意push的是同一个Batch的，是来自同一个域的数据，将同一批次（域）中的 BEV 向量在表示空间中push彼此是因为，由于负对样本来自单个域并共享相同的域属性，因此学习与域无关的表示。而pull是将共享相同语义内容但与表示空间中接近的不同批次（域）的 BEV 向量靠近来促进网络联合学习与域无关的特征。

v3(2025上半年)
上次写v2时对e2e具体怎么做的认知, 还只是靠自己的想象. 回看了一下, 虽然原理没问题, 但是想真的训练出来一个这样的world model, 难度巨大, 因为:
输入history video, 预测future video, 大量计算被浪费在背景的那些pixel space上
从而导致这样的模型, 需要model capacity足够大也就是参数足够多, 相应的需要的数据也要足够多
从而导致训练, 部署, 数据生产, 都不是很现实

2. 所以要把无意义的背景去掉, 只预测和自车planning有关系的那部分信息就可以. 具体做法我们投了一篇cvpr2025, 方法非常简洁, 效果也SOTA, 同时做法上也比较独一无二, 结果是442被拒了

3. 从实际工程角度出发, 能部署上车的方案, 非常推荐para-drive这种范式。可以先把para-drive做到量产水平, 如果有足够算力的话做个加法接上vlm锦上添花一下，把vlm的输出给planning head，以解决一些long tail问题

4. 再进一步就到了VLA了，当前算力背景下快慢系统的设计还是要保留，VLM输出轨迹不够精确的问题也要解决，所以最近主流趋势是VLM（低频推理） + head（高频推理），VLM先出一些粗粒度信息（决策，或者不精确的轨迹），head优化成精细的可以执行的轨迹，比如pi0，hamster等，比较推荐nvidia的hamster这种做法

5. 一个持续回答了2年的问题, 竟然依然还没有跑题, 这些方案依旧是基于bev feature来作为中间表示的. 随着这两年的技术变化, 我们也可以看到一个大的趋势: 自动驾驶, 正在朝着端的越来越极致的方向在发展

v2(2024上半年)
技术发展很快，上次回答还仅仅局限在bev本身。随着LLM和diffusion model的火爆，这些趋势也在向自动驾驶蔓延。所以自动驾驶的下一步，应该是world model(作为整体backbone) + multi-task head来取代现在的感知-预测-决策-规控的模块化方式。

2. world model代表了一个模型对其所负责的领域的基础理解能力，而反应理解水平的最佳方式就是可以准确的做出对未来的预测。

3. LLM是根据上文预测next token，我们可以说他对人类的自然语言有了一个基本的理解。openAI 首席科学家 Ilya Sutskever 前段时间接受的一个采访也提到：大语言模型看起来所做的事情是预测下一个词，但实际上在这个过程中，大语言模型学会了表征这个世界，是一个世界模型。

4. 自动驾驶场景中也一样，如果输入前面几帧image，模型可以预测出来后面几帧，这个模型就对自动驾驶场景有了基本的理解能力。

5. 只不过语言是人类高度抽象出来的，信息熵高，视觉是天然的，信息熵低，所以训练一个具有更大压缩比的视觉world model更难，需要巨大的数据和算力。

6. 这个world model，其输入可以是多模态，比如加上场景描述text，驾驶action，导航信息等等，这些模态经过encode后作为生成模型的condition. 但是因为自动驾驶camera都是multi view的，如果生成multi view，耗费更大的计算资源不说，multi view之间的同步性也不好控制，所以可以基于bev space来用diffusion model做生成

7. 有了这样的一个world model后，我们就可以利用其对未来的预测能力，再增加一个planning head继续进行finetune，预测出未来的planning或者要采取的action。

8. 最近也有一些paper在做这个方向，比如drivedreamer，gaia-1等。

v1(2023年)
先回答问题
现在bevformer和voxel pooling平分秋色，但是这种dense的方法感知范围都会受到算力限制

2. 下一步应该是基于sparse的表示，计算复杂度不受感知范围影响

dense方法
voxel pooling不仅仅在hw维度上dense，在depth上也dense，比较浪费计算，但是优点是把2d feature投到了所有的depth bin中，理论上不同depth上feature不同，可能会对depth估计更准。

2. 而bevformer正好反过来，是把3d往2d投，在远处的时候，经常会出现一个ray上的3d点被投到了相同的2d点，远处经常深度估计不准，经常出现预测一串物体的现象。

关于representation
普通的2d detection，从anchor based到point based（centernet），再到detr系列，和深度学习相关的东西的本质是没有变的，变化的只是对问题的表示方式, 即representation。

2. bev也是如此，从后融合不同camera的3d detection，到直接从网络出来bev detection，变化的也只是representation。

3. 所以, 对物体的表示方法，是朝着越来越精简和优雅的方向来发展的，比bev更好的representation，也是bev后面的发展方向。bev这种方式，在于从表示方法上的创新，他该有的问题一样有，比如depth估计不准，比如长尾分布带来的corner case。

从信息论的角度
一个通信系统，包括信源，编码，信道，解码，信宿。对于神经网络来说，信源就是网络输入，编码和解码都是网络结构，信宿就是输出，可以认为没有信道，或者是一个identity的信息传输通道。

2. 以下的任何一个模块的创新，都可以成为bev下一步的发展方向。

同样的模型，输入融合camera和lidar等多种传感器，比单纯输入camera效果要好，因为提供了更多的信息。
同样的输入，使用不同的编码，效果也不一样。比如刚才提到的bevformer和voxel pooling就是不一样的编码方式。还有MLP和IPM这两种效果不太好的。
bevformer v2，可以认为是改进的解码部分，增加了mono3d head作为decoder的一部分reference points。
如何做sparse
大体思路：init一组bev坐标系下的reference points（比如900个），然后投到2d space在2d feature做sample。时序，就是把这组reference points根据ego pose得到t-1的points，去t-1的2d feature上sample, 但是这样做计算量有点大, 可以像sparse4d这样, history query取topk和当前帧query concat, 即query propagation的方式

2. 这样做原理是没有问题的，但是还有一些细节上的问题。比如ref points是随机初始化的，可能难以收敛，这个可以通过给ref points增加先验解决（可以是bevformer v2的方式，也可以加一些radar先验作为一部分query, 也可以是sparse4d这种方式, 统计数据集分布作为anchor）
