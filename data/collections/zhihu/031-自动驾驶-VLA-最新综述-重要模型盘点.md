# 自动驾驶 VLA 最新综述：重要模型盘点

> 作者: 郑深 | 来源: https://zhuanlan.zhihu.com/p/1948896079941731927

---

前言

最近有篇很火的自动驾驶综述：

之前在这篇文章里，我梳理了VLA最新综述的要点，以及个人见解。

上文中讲到，模型可以分为四类（下面的Figure3取自综述论文）

VLM as Driving Explainer: VLM 帮你分析场景，和给出指令，但具体怎么开还得自己决定。
Modular VLA for AD: VLM 输出语义表征，Action Head通过表征，决定高层轨迹。
End-to-end VLA for AD: VLM 直接输出高层轨迹和低层执行。
Augmented VLA for AD: VLM 不仅直接输出高层轨迹和低层执行，还结合推理、记忆或外部工具，做更复杂的推理和决策。




下面就来讲下每类比较有代表的模型。

1. VLM as Driving Explainer
DriveGPT-4

研究背景

现有自动驾驶的 VLM 多停留在场景解释，缺少统一框架来同时支持“语言理解 + 控制预测”。

解决方案

多模态输入：多帧视频通过 Visual Encoder 编码，自然语言问题通过 Text Tokenizer 编码。
统一 LLM 框架：视频特征经 Projector 转换后，与文本特征一起输入大语言模型统一处理。
双输出通道：既能生成自然语言解释（e.g., “前方无障碍，车辆直行”），又能直接预测控制信号（速度、转向角）。
两阶段训练：先在大规模视频/图像上预训练（对齐视觉与语言），再用 BDD-X 和 ChatGPT QA 指令微调，提升推理和泛化。




2. Modular VLA for AD
OpenDriveVLA

研究背景

现有自动驾驶 VLM 多停留在场景解释，缺少统一框架来同时支持“语言理解 + 轨迹规划”

解决方案

视觉输入：环视相机图像经过 Vision Encoder 编码成 BEV 特征，再由 EnvQFormer 提取场景、地图和交通体 token。
文本输入：驾驶指令与 Ego 状态通过 Textual Encoder 转为 token。
跨模态融合：视觉 token 经 Projector 投射到语言空间，与文本 token 在 LLM 内统一处理。
行动输出：LLM 融合后在视觉 token（场景/地图/交通体）、驾驶指令和自车状态的条件下，自回归生成离散化的轨迹 token，并解码为未来自车轨迹。
CoVLA-Agent

研究背景

现有自动驾驶 VLM 多偏向于场景理解（如描述或问答），缺乏能同时执行语义理解 + 轨迹预测 的统一框架。

解决方案

视觉输入：前向相机图像经 CLIP ViT-L 提取视觉特征。
文本输入：场景描述及 Ego 速度，经 Text Tokenizer 与 MLP 编码。
跨模态融合：视觉特征、速度 embedding 与文本 embedding 拼接后输入 Llama-2 (7B)，统一建模。
双任务输出：
文本输出：生成交通场景描述；
轨迹输出：生成未来 3 秒的 10 个轨迹点。
DriveMoE

研究背景

现有端到端自动驾驶 VLA 模型存在两大问题：（1）视觉端：环视相机处理冗余视图，导致 token 过多、计算低效；（2）行动端：统一策略头容易对常见行为过拟合，而难以覆盖稀有、复杂驾驶技能

解决方案

视觉输入：多相机图像通过 Scene-Specialized Vision MoE，由路由器动态选择与当前场景相关的关键视角，再经投影层融合为视觉表示。
文本与状态输入：固定指令提示（如 “预测未来轨迹”）与 Ego 状态（位置、速度、航向等）转为 token 输入。
跨模态融合：视觉表示、文本 token 与状态 token 一起送入预训练 VLM（Paligemma）处理。
行动输出：Skill-Specialized Action MoE 在流匹配规划器中，按驾驶意图激活对应专家（如并线、超车、避障、紧急制动），生成未来轨迹。
LangCoop

研究背景

现有多车协同自动驾驶方法依赖传感器数据或特征通信，存在带宽开销大、异构车辆不兼容、信息丢失等问题。

解决方案

视觉输入：每辆车前视图像输入 LVLM，经M³CoT 模块 分阶段推理（场景描述、对象识别、导航目标、未来意图），获得结构化语义信息。
语言打包：通过 LangPack 将场景、对象、目标、意图等压缩成 <2KB 的自然语言包，发送给其他车辆。
跨车协同：各车接收并整合来自其他车辆的 LangPack，与自身感知结果合并输入 LVLM。
行动输出：生成三类驾驶信号：离散轨迹、连续轨迹或直接控制命令（转向、油门、刹车），实现多车协同决策与控制。
SafeAuto

研究背景

现有基于 MLLM 的自动驾驶多是纯数据驱动，常出现控制预测不准、忽视交通规则，导致驾驶行为不安全。

解决方案

改进低层预测：提出 Position-Dependent Cross-Entropy (PDCE) Loss，对近距离的未来点加大约束，让速度和转向预测更精准稳定。
例如：预测“下一秒转向角”必须很准，否则就可能偏离车道；而 10 秒后的方向可以允许有点误差。

安全知识验证：将交通规则转为一阶逻辑，嵌入 Markov Logic Network，对 MLLM 输出的动作做安全校验，过滤掉违规或危险行为。
例如：如果模型输出“红灯左转”，逻辑规则会立刻拦下来，确保不违规。

经验增强决策：通过 Multimodal RAG，从历史视频、控制信号和场景描述中检索相似的驾驶经验，为当前复杂场景提供参考。
例如：遇到少见的施工路段时，模型会回忆“之前在类似工地路口是怎么绕行的”，从而做出更合理的动作。
RAG-Driver

研究背景
现有基于 MLLM 的自动驾驶模型虽然能解释动作，但泛化性差：数据标注昂贵、跨域迁移困难，一旦换场景就容易“失忆” 。

解决方案

视觉输入：驾驶视频经过预训练 Video Encoder（LanguageBind），提取时序视觉特征并投射到语言空间。
文本与任务指令：结合控制信号和自然语言提示（如“描述当前驾驶动作”），统一输入 LLM。
检索增强 (RA-ICL)：从记忆库中检索相似驾驶经验（视频+控制+解释），作为 In-Context Learning 示例前缀，辅助模型推理。
多任务输出：模型同时生成
驾驶动作解释（e.g. “车辆正在减速准备右转”）；
动作理由（e.g. “因为前方有红灯”）；
数值控制信号（速度、转向角）。
3. End-to-end VLA for AD
EMMA

研究背景
传统自动驾驶多采用感知-预测-规划的模块化流水线，容易积累误差，难以在新场景中泛化。而现有端到端方法又常局限于单一任务，缺乏统一处理多任务的能力EMMA。

解决方案

视觉输入：环视相机视频输入，捕捉环境场景。
文本输入：高层导航指令与 Ego 历史状态，以自然语言 token 表示。
统一建模：所有输入与输出（轨迹、3D物体、道路图元素）都转化为文本，由 Gemini 统一处理，并可结合 Chain-of-Thought 推理生成解释性理由。
多任务输出：同时预测未来规划轨迹、场景中 3D 目标、道路拓扑要素及场景语义，实现从感知到规划的一体化。
SimLingo

研究背景

现有将 VLM/LLM 用于自动驾驶的工作，常把“语言理解”和“驾驶动作”分开评估，容易出现 能读懂却开不对 的脱节问题；同时闭环多依赖多传感器，难以在纯视觉下兼顾语言与驾驶表现。

解决方案

视觉输入：仅用摄像头图像提取时序视觉表示（纯视觉、闭环）。
导航/任务输入：支持语言导航（HLC）或目标点（TP），连同任务提示一并写入文本序列。
统一建模：将图像与文本 token 交错喂入轻量 LLM，完成语言理解/解说，再用动作查询生成轨迹表征。
行动输出：采用解耦轨迹（几何路径航点 + 速度航点），经 PID 转成转向与油门/刹车，实现闭环控制。
语言-动作对齐：Action Dreaming 为同一画面合成多种“指令—动作”对，训练模型按指令行事而非只做视觉捷径。
ADriver-I

研究背景
传统自动驾驶采用“感知–预测–规划–控制”的模块化流水线，虽然可解释，但容易累积误差且依赖大量先验（如3D框、HD Map）。现有端到端方法多只能做控制预测或场景生成，缺乏统一框架。

解决方案

视觉输入：前视视频帧经过 CLIP-ViT 编码，再适配到语言空间形成视觉 token。
动作输入：历史速度、转向角等低层控制信号转成文本 token，与图像 token 交错，构成“vision–action pair”。
统一建模：多模态大语言模型 (Vicuna-7B) 读取当前帧 + 历史 vision–action pairs，自回归输出当前控制信号。
未来生成：控制信号作为条件，输入视频扩散模型 (VDM) 生成未来帧场景；生成的新帧再回流 MLLM 预测后续动作。
行动输出：循环执行“预测动作–生成场景”，实现类似人类的 “边看边开 + 预判未来”的闭环驾驶，可在自身生成的世界里“无限驾驶”。
DiffVLA

研究背景
现有端到端自动驾驶虽能统一感知与规划，但 BEV 计算昂贵、轨迹预测缺乏多样性，在复杂场景中决策容易次优。

解决方案

视觉输入：多相机图像输入 VLM，引导生成候选轨迹与高层驾驶命令。
感知输入：采用稀疏+稠密混合感知，稠密分支生成 BEV 特征图，稀疏分支输出实例级物体与地图元素，二者结合获得全局与结构化信息。
统一建模：VLM 输出与混合感知结果作为条件，送入扩散式规划模块。
扩散规划：基于截断扩散策略，用离散化轨迹词表与多模态锚点逐步去噪，生成多样化未来轨迹。
行动输出：输出预测轨迹（waypoints），实现更加高效、多样和鲁棒的闭环驾驶。
4. Augmented VLA for AD
ORION

研究背景

现有端到端自动驾驶方法虽然能把感知、预测、规划整合在一起，但常因缺乏因果推理能力，在复杂交互场景下决策失误；而直接使用 VLM 输出文本规划，又与数值轨迹输出存在语义–数值鸿沟

解决方案

视觉输入：多相机图像经过视觉编码器提取特征。
长时记忆：QT-Former 引入场景查询、感知查询和历史查询，聚合长时视觉上下文，捕捉交通元素与历史状态。
推理建模：LLM 接收场景 token、历史 token 与文本指令，执行场景理解与推理，并生成规划 token。
生成式规划器：以规划 token 为条件，采用 VAE 等生成模型在潜在空间对齐“推理空间–动作空间”，输出多模态未来轨迹。
行动输出：轨迹解码为转向、加速、刹车等控制信号，实现解释性强且鲁棒的闭环驾驶。
AutoVLA

研究背景
现有端到端自动驾驶 VLA 模型常出现两大问题：一是直接生成的轨迹可能物理不可行或结构复杂，二是推理策略固定，既不能在简单场景快速响应，也无法在复杂场景充分解释，导致效率与可用性受限。

解决方案

视觉输入：多视角相机序列输入 Vision Encoder，提取时序环境特征。
文本与状态输入：高层导航指令、Ego 状态（速度、加速度、历史动作）转为 token，与视觉特征拼接。
统一建模：基于 Qwen2.5-VL-3B 的 VLM 主干，扩展输出物理动作 token（∆x, ∆y, ∆θ），把规划转化为语言模型的自回归预测问题。
双模式推理：在监督微调 (SFT) 阶段同时学习 Fast Thinking（直接输出动作 token）和Slow Thinking（CoT 推理 + 动作 token），使模型能按场景复杂度切换。
强化微调：提出基于 GRPO 的强化训练 (RFT)，引入奖励函数（安全、舒适、效率）并对冗余推理加惩罚，使模型在简单场景快速决策，在复杂场景理性推理。
行动输出：自回归生成动作 token 序列，再解码为 5 秒规划轨迹，映射到转向、加速、刹车控制，实现可解释且高效的闭环驾驶
核心趋势与未来方向

从“翻译官”到“驾驶脑” → 世界模型与因果推理
VLM 已从场景翻译者进化为“驾驶脑”，直接参与规划与控制。但要成为真正的世界模型，它必须不止会预测“会发生什么”，还要理解“为什么会发生”，具备因果推理来应对极端长尾场景。

端到端与可解释性的平衡 → 极致安全性
VLA 正在打破“黑箱”，既能端到端决策，又能生成理由解释。但这也意味着它的决策会直接影响安全。因此未来必须结合逻辑校验、形式化验证，确保任何情况下都不会输出危险动作。

经验与知识的双重赋能 → 更深的多模态融合
通过 RAG 回忆经验、逻辑网络嵌入规则，VLA 已经像老司机一样“既懂经验又守规则”。下一步挑战是让它接入更多传感器（雷达、激光雷达、IMU），把知识与多模态数据结合，进一步提升鲁棒性。

效率与性能的再平衡 → 新评测体系
MoE、快慢思维推理表明，业界在追求算力效率与实时性的平衡。但评估标准也必须升级：不只是轨迹精度或里程，还要衡量它的理解、推理、解释和泛化，才能真正反映模型的“驾驶智商”。
