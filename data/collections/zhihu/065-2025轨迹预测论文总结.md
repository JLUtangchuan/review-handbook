# 2025轨迹预测论文总结

> 作者: Lime | 来源: https://zhuanlan.zhihu.com/p/1892876738373060311

---

TL；DR

好久没读论文了，关于轨迹预测的相关论文都有些忘了，因此想通过整理一个简洁版的文章，系统的整理一下近几年来轨迹预测方向比较好的论文

1. MTR

Goal Base，Single agent，agent centric。本文最核心的创新点就是采用anchor的思路，给定指定目标点的监督(这一点在TNT中也有过类似的结论，轨迹预测，最难的还是目标轨迹点的预测)，然后先通过多层refine（agent采用全局交互，map采用refine轨迹末端点轨迹采样map特征进行局部交互），最终输出轨迹（64条轨迹，论文中利用k-means聚类了64个anchor），在训练阶段采用WTA策略训练，在推理阶段通过NMS选取K条轨迹。

直观的解释一下论文框架图，左半部分是特征提取部分，其中[K x 1 x 2]的代表K-means聚类的K（64）个anchor，[K x (2 + 2)]代表static intention point和dynamic intention point（但是看代码，静态intentionpoint在后续步骤中没有使用，只在初始化query content使用了），[K x D]代表交互的query特征。

2.MTR++
MTR Framework
MTR++ Framework

multi agent，query centric。这里直观的展示了MTR和MTR++的差异，首先是特征编码部分，选用的encoder都是PointNet(MLP+MaxPool),但是特征输入没有采用agent centric的方式，而是query centric(通俗来说就是将每个agent norm到agent 自身的坐标系下)，同时属性出了上述norm特征，还包含norm之前全局的坐标和heading角，这就是原文说的Symmetric Scene Context Modeling。

特征编码完成之后，为了完成token self attention，这里文章采用了Symmetric Scene Context Modeling with Query-Centric Self-Attention方案，这里和上述的query centric不太一样，采用的还是agent centric的相同的方式，对每个query token（包含agent 和 map）采样k个最近的token，之后将k个token转换到当前token的agent坐标系进行attention。

为了增强模态间的自洽性，MTR++的第二个重要的模块是Joint Motion Decoder，这里简单来说就是将原来的agent centric不存在的问题针对多目标预测任务进行了适配，对anchor进行了反变换，anchor转化为全局坐标系，之后再进行motion query初始化，其他同MTR之后采用了和上述self attn相同的操作，对所有agent的所有modality进行了合并，之后采用k个最近的token 转换到当前 agent坐标系进行cross attention，之后所有的流程就和MTR一样了。

3.MTR v3

multi agent，query centric。这里只有一分report，并没有完整的论文和代码，从原文论文主要包含两个创新点，在MTR++的基础上，首先是融入了lidar信息，加入了lidar特征。同时关于lidar特征的local attention，作者设计了一种对齐策略，然后采样k个lidar query特征进行local attention。第二个是采用了Ensemble方法进行了刷点，其他方案同MTR++。

4.MultiPath

anchor base，采用了K-means聚类预处理得到anchor。方案采用了rasterization representation方式，对于每个agent，采样局部的scene features。之后对回归轨迹（这里文章说的不是特别清晰具体的回归方案，只是说使用anchor进行参数初始化），只监督距离gt最近的anchor对应的轨迹，监督reg和cls。

5.MultiPath++

single agent， agent centric。Multipath++源于Multipath，首先分析一下Multipath方案的创新点，首先是特征的稠密表达，第而是采用了static anchor避免了模态坍塌。稠密表达特征稀疏计算量大，同时存在像素空间与实际位置对齐问题，且全部特征交互能力较差；static anchor普适性差。基于上述分析，作者提出了Multipath++

使用RNN编码Polyline的Map特征
使用MCG（类似cross attention）进行特征交互
loss还是采用了GMM loss（混合高斯分布）(关于GMM loss的理解，可以参考Lime：通俗理解GMM Loss)
去除静态anchor
集成学习提点

这里直观的展示了Multipath++和其他方案的编解码对比。

这里展示了Multipath++模型框架图，下面结合代码和图文进行分析（https://github.com/stepankonev/waymo-motion-prediction-challenge-2022-multipath-plus-plus?tab=readme-ov-file）

MCG bloc

这里s有点类似于attention中的query，c类似k，v

\begin{align} \tilde{\mathbf{s}}_i &= \text{MLP}(\mathbf{s}_i) \\ \tilde{\mathbf{c}} &= \text{MLP}(\mathbf{c}) \\ \mathbf{s}'_i &= \tilde{\mathbf{s}}_i \odot \tilde{\mathbf{c}} \\ \mathbf{c}' &= \text{Pool}(\mathbf{s}'_{1:n}), \end{align}

\begin{align} \overline{\mathbf{s}}^{k}_{1:n} &= \frac{1}{k} \sum_{j=1}^{k} \mathbf{s}^{j}_{1:n} \\ \overline{\mathbf{c}}^{k} &= \frac{1}{k} \sum_{j=1}^{k} \mathbf{c}^{j} \\ (\mathbf{s}^{k+1}_{1:n}, \mathbf{c}^{k+1}) &= \text{CG}\left(\overline{\mathbf{s}}^{k}_{1:n}, \overline{\mathbf{c}}^{k}\right). \end{align}

如上述两个公式分别代表了CG block和stack CG block的计算方法，CG block计算还是比较简单的，stack CG block有两点，第一是使用了residual方法，第二个是对所有的s和c进行平均。

接下来看一下代码

class CGBlock(nn.Module):
    def forward(self, scatter_numbers, s, c):
        prev_s_shape, prev_c_shape = s.shape, c.shape
        s = self.s_mlp(s.view(-1, s.shape[-1])).view(prev_s_shape)
        c = self.c_mlp(c.view(-1, c.shape[-1])).view(prev_c_shape)
        s = s * c
        if self._config["agg_mode"] == "max":
            aggregated_c = torch.max(s, dim=1, keepdim=True)[0]
        elif self._config["agg_mode"] in ["mean", "avg"]:
            aggregated_c = torch.mean(s, dim=1, keepdim=True)
        else:
            raise Exception("Unknown agg mode for MCG")
        return s, aggregated_c


    
class MCGBlock(nn.Module):
    def _repeat_tensor(self, tensor, scatter_numbers, axis=0):
        result = []
        for i in range(len(scatter_numbers)):
            result.append(tensor[[i]].expand((int(scatter_numbers[i]), -1, -1)))
        result = torch.cat(result, axis=0)
        return result

    def _compute_running_mean(self, prevoius_mean, new_value, i):
        if self._config["running_mean_mode"] == "real":
            result = (prevoius_mean * i + new_value) / i
        elif self._config["running_mean_mode"] == "sliding":
            assert self._config["alpha"] + self._config["beta"] == 1
            result = self._config["alpha"] * prevoius_mean + self._config["beta"] * new_value
        return result

    def forward(
            self, scatter_numbers, scatter_idx, s, c=None, aggregate_batch=True, return_s=False):
        if c is None:
            assert self._config["identity_c_mlp"], self._config["identity_c_mlp"]
            c = torch.ones(s.shape[0], 1, self.n_in, requires_grad=True).cuda()
        else:
            assert not self._config["identity_c_mlp"]
        c = self._repeat_tensor(c, scatter_numbers)
        assert torch.isfinite(s).all()
        assert torch.isfinite(c).all()
        running_mean_s, running_mean_c = s, c
        for i, cg_block in enumerate(self._blocks, start=1):
            s, c = cg_block(scatter_numbers, running_mean_s, running_mean_c)
            assert torch.isfinite(s).all()
            assert torch.isfinite(c).all()
            running_mean_s = self._compute_running_mean(running_mean_s, s, i)
            running_mean_c = self._compute_running_mean(running_mean_c, c, i)
            assert torch.isfinite(running_mean_s).all()
            assert torch.isfinite(running_mean_c).all()
        if return_s:
            return running_mean_s 
        if aggregate_batch:
            return scatter_max(running_mean_c, scatter_idx, dim=0)[0]
        return running_mean_c

上述代码来源于mpp++官方仓库代码，结合公式，可以直观看出处理方法，就是不断refine一个平均特征。

之后解释一下cross attention和MCG的区别，简单来说就是cross attention是s[B, A, H]（A个特征）与c[B, M, H]（M个特征），所有的特征之间进行attention，复杂度为O(AM);而对于MCG block，相当于对c[B, M, H]在M这个维度进行了Pool处理，使其shape变为[B, 1, H]，进而降低复杂度。参考下图。

上述解释了整个MCG block，整体上还是特别清晰的。

class Decoder(nn.Module):
    def __init__(self, config):
        super().__init__()
        self._config = config
        self._return_embedding = config["return_embedding"]
        self._learned_anchor_embeddings = torch.empty(
            (1, config["n_trajectories"], config["size"]))
        stdv = 1. / math.sqrt(config["size"])
        # stdv = 1. / config["size"]
        # nn.init.xavier_normal_(self._learned_anchor_embeddings)
        self._learned_anchor_embeddings.uniform_(-stdv, stdv)
        self._learned_anchor_embeddings.requires_grad_(True)
        self._learned_anchor_embeddings = nn.Parameter(self._learned_anchor_embeddings)
        self._mcg_predictor = MCGBlock(config["mcg_predictor"])
        if not self._return_embedding:
            self._mlp_decoder = NormalMLP(config["DECODER"])
    
    def forward(self, target_scatter_numbers, target_scatter_idx, final_embedding, batch_size):
        # assert torch.isfinite(self._learned_anchor_embeddings).all()
        assert torch.isfinite(final_embedding).all()
        trajectories_embeddings = self._mcg_predictor(
            target_scatter_numbers, target_scatter_idx, self._learned_anchor_embeddings,
            final_embedding, return_s=True)
        assert torch.isfinite(trajectories_embeddings).all()
        if self._return_embedding:
            return trajectories_embeddings
        # 
        res = self._mlp_decoder(trajectories_embeddings)
        coordinates = res[:, :, :80 * 2].reshape(
            batch_size, self._config["n_trajectories"], 80, 2)
        assert torch.isfinite(coordinates).all()
        a = res[:, :, 80 * 2: 80 * 3].reshape(
            batch_size, self._config["n_trajectories"], 80, 1)
        assert torch.isfinite(a).all()
        b = res[:, :, 80 * 3: 80 * 4].reshape(
            batch_size, self._config["n_trajectories"], 80, 1)
        assert torch.isfinite(b).all()
        c = res[:, :, 80 * 4: 80 * 5].reshape(
            batch_size, self._config["n_trajectories"], 80, 1)
        assert torch.isfinite(c).all()
        probas = res[:, :, -1]
        assert torch.isfinite(probas).all()
        if self._config["trainable_cov"]:
            # http://www.inference.org.uk/mackay/covariance.pdf
            covariance_matrices = (torch.cat([
                torch.exp(a) * torch.cosh(b), torch.sinh(b),
                torch.sinh(b), torch.exp(-a) * torch.cosh(b)
            ], axis=-1) * torch.exp(c)).reshape(
                coordinates.shape[0], coordinates.shape[1], coordinates.shape[2], 2, 2)
        else:
            _zeros, _ones = torch.zeros_like(a), torch.ones_like(a)
            covariance_matrices = torch.cat([_ones, _zeros, _zeros, _ones], axis=-1).reshape(
                coordinates.shape[0], coordinates.shape[1], coordinates.shape[2], 2, 2)
        return probas, coordinates, covariance_matrices

直接从代码说吧，这里直接随机初始化了self._learned_anchor_embeddings，也就是最后出轨迹和概率的query，这里其实和anchor没那么大关系，感觉作者更像是为了关联multipath的static anchor概率，取的一个名字，这里就是一个普通的query embedding，通过MCG交互，之后接mlp，实现轨迹和概率预测，文章中用了多层decode。

6.GameFormer

scene centric, multi agent prediction。模型主题结构如上，左边是编码部分，右边是文章主要创新点level-k解码结构,其中agent encoder采用lstm，map encoder采用mlp。之后利用level-k解码，这里的level-0是一个采用agent encoding初始化的query和scene context进行cross attention；之后迭代更新future encoding，并将future encoding和scene context concat之后进行cross attention输出轨迹和概率。

7.VAD

传统的端到端分模块方案容易导致累计误差；最近的一些端到端的方案直接采用传感器输入，出planning轨迹，难以训练；同时还有许多方案采用传感器输入转化为dense representation(semantic map, occupancy map, flow map, and cost map)，提供给planning消费。因此作者基于sparse representation，设计了端到端预测方案。

vectorized map 以及 vectorized motion很多方案都有使用。这里从框架图来看，使用周视图像编码BEV特征，之后训练map和motion，通过上下两条线，分别解码motion合map，进行监督。同时将得到的motion和map隐式特征与ego query（很多基于anchor Vocabulary list的初始化方式，类似MTR，不过文章中采用了随机初始化的方式）进行拼接，同时融入ego status以及driving command信息，出planning轨迹，通过collision loss以及其他相关loss进行planning轨迹监督。

这里给出了VAD的三种loss 图示。

8.VAD v2

上图展示了文章方案概率规划（probabilistic planning）同其他规划方案的区别，类似于prediction 多模态的轨迹，这里引入了概率规划模型，仅使用camera信息再开闭环评测上取得了SOTA。

上图展示了VADv2的框架

其中场景信息编码主要图中的M，A，T，I（map feat，agent feat，traffic state feat（红绿灯，停止线）,以及原始的 image feat），同时编码了ego state 以及 navigation info信息。

对于probabilistic planning，相较于VAD v2，文章引入了vocabulary list，也就是anchor的方案，采用anchor初始化ego query。之后利用collision loss等进行监督。整体方案特别简洁。

9.HIVT

图示展示了HIVT的方案框架，简单来说就是局部交互和全局交互。

其中局部交互采用agent centric 的信息编码方式，这里局部交互包含在时间维度，障碍物与局部区域其他障碍物进行交互，得到T个特征，之后T个特征在空间维度进行self attentio，最后和local lanes进行交互，得到agent的局部特征编码。

对于全局特征交互，将上述得到局部特征同其他所有局部特征进行cross attention。

最后采用mlp进行解码和监督。

文章的主要思路简单来说就是分层交互，实现计算量的缩减。

10.QCNet

query centric，multi agent prediction。为了解决在线流式推理过程中传统方法需要在每帧重复re-norm所有agent特征，文章提出在每一个时刻，对于每一个agent进行局部信息编码，以此达到特征复用的目的。

基于上述得到的局部编码特征，进行如图所示特征交互编码。

对于解码部分，方案采用了两阶段的decoder，首先解码得到proposed trajectory。之后利用上述解码的proposed trajectory作为anchor进行offset预测，预测轨迹和概率。还没有看代码，具体的细节，后续补上。

11.HPNet

针对帧间预测稳定性问题，作者提出了HPNet，在流式预测中引入历史预测embeding，用于增强预测稳定性，在原有的Agent attention和Mode Attention基础上，引入historical prediction attention，组成三阶段的attention方案。由于historical prediction的引入，也增大了当前帧感知范围。

引入历史query embeding

上图展示了HPNet的方案同传统静态预测方案对比，HPNet将历史预测引入当前帧。

这里直观的展示了HPNet整体框架，这里首先通过agent cross attention和map cross attention获取motion encoding feat，之后获取将上述得到的embedding通过N次triple factorized attention进一步进行信息交互，最后通过MLP解码多模态预测。通过将多模态预测结果直接用于初始化下一帧的mode queries，整体特别简洁。

12.TNT

single agent(可以拓展到multi agen)，TNT主要包含三个步骤：采样anchor，预测轨迹，anchor概率预测。简单来说就是预定义N个anchor，之后利用一个mlp预测anchor概率和offset得到预测终点，最后根据终点回归整个预测轨迹。下面结合代码进行分析

    def forward(self, data):
        """
        output prediction for training
        :param data: observed sequence data
        :return: dict{
                        "target_prob":  the predicted probability of each target candidate,
                        "offset":       the predicted offset of the target position from the gt target candidate,
                        "traj_with_gt": the predicted trajectory with the gt target position as the input,
                        "traj":         the predicted trajectory without the gt target position,
                        "score":        the predicted score for each predicted trajectory,
                     }
        """
        n = int(data.candidate_len_max[0].cpu().numpy())

        target_candidate = data.candidate.view(-1, n, 2)   # [batch_size, N, 2]
        batch_size, _, _ = target_candidate.size()
        candidate_mask = data.candidate_mask.view(-1, n)

        # feature encoding
        global_feat, aux_out, aux_gt = self.backbone(data)             # [batch_size, time_step_len, global_graph_width]
        target_feat = global_feat[:, 0].unsqueeze(1)

        # predict prob. for each target candidate, and corresponding offest
        target_prob, offset = self.target_pred_layer(target_feat, target_candidate, candidate_mask)

        # predict the trajectory given the target gt
        target_gt = data.target_gt.view(-1, 1, 2)
        traj_with_gt = self.motion_estimator(target_feat, target_gt)

        # predict the trajectories for the M most-likely predicted target, and the score
        _, indices = target_prob.topk(self.m, dim=1)
        batch_idx = torch.vstack([torch.arange(0, batch_size, device=self.device) for _ in range(self.m)]).T
        target_pred_se, offset_pred_se = target_candidate[batch_idx, indices], offset[batch_idx, indices]

        trajs = self.motion_estimator(target_feat, target_pred_se + offset_pred_se)

        score = self.traj_score_layer(target_feat, trajs)

        return {
            "target_prob": target_prob,
            "offset": offset,
            "traj_with_gt": traj_with_gt,
            "traj": trajs,
            "score": score
        }, aux_out, aux_gt

    def inference(self, data):
        """
        predict the top k most-likely trajectories
        :param data: observed sequence data
        :return:
        """
        n = data.candidate_len_max[0]
        target_candidate = data.candidate.view(-1, n, 2)    # [batch_size, N, 2]
        batch_size, _, _ = target_candidate.size()

        global_feat, _, _ = self.backbone(data)     # [batch_size, time_step_len, global_graph_width]
        target_feat = global_feat[:, 0].unsqueeze(1)

        # predict the prob. of target candidates and selected the most likely M candidate
        target_prob, offset_pred = self.target_pred_layer(target_feat, target_candidate)
        _, indices = target_prob.topk(self.m, dim=1)
