一篇在非智驾团队的知识分享，综述了一下自动驾驶视觉模型的发展历程和当前形态。

自动驾驶算法架构

传统的自动驾驶算法结构由三大模块组成：感知融合、定位建图、预测规划控制。定位与感知输出从不同传感器得来的障碍物和可行驶区域在三维世界的投影，交由给融合模块去判断，最后交给规划模块去预测与让车辆做出最后的决策。
定位建图：定位建图通过融合卫星导航（GNSS）、惯性导航（IMU）等多源传感器数据，结合静态环境感知结果，构建高精地图，并在此基础上实现车辆在环境中的高精度定位。高精地图采集成本高，全国整体覆盖率不足 10%。因此需要更强的感知能力应对各种泛化场景。
感知融合：接收来自摄像头、激光雷达、毫米波雷达、超声波、IMU 等多种传感器的数据，通过信息同步、空间对齐和语义整合等处理手段，将不同来源的感知结果进行融合，输出车道线、障碍物、动态目标轨迹、路沿、交通标志、交通信号状态等高语义层级的环境信息，为行为决策与轨迹规划提供全面、精确和稳定的环境感知支持。
规划控制：以感知输出（道路结构、动态障碍、占用信息、交通状态）为输入，结合加速度与舒适性约束，输出一条平滑、可控的路径点序列，用于引导车辆在未来固定时间内执行预期行为（如跟车、绕行或礼让）。传统的规划控制包含各种详细规则去处理各种问题。

发展路线
2D 感知与属性识别：初期自动驾驶感知算法主要依赖单帧 2D 图像，专注于物体的检测与分类，同时尝试识别物体的基本属性（如类别、尺寸）。etc：yolo
单目 3D 感知：随着深度学习的发展，感知系统逐步具备从单张图像中恢复深度的能力，从而进行三维物体定位，但精度受限于深度估计误差。etc：mono3d
环视 3D 感知：引入多个相机，通过多视角图像融合构建空间一致的 BEV 表征，大幅提升对全场景空间的理解能力，增强了鲁棒性。etc：fastbev
时序环视 3D 感知：在环视 3D 感知的基础上，引入了时间维度的考量，通过连续帧的变化融合，增强了对动态环境的感知能力。etc：streampetr/sparse4D
多传感器融合：在多摄感知基础上，引入时间维度，通过融合多帧图像或 BEV token，提升模型对动态场景中物体轨迹、速度的建模能力。代表作：bevfusion
端到端模型（世界模型）：当前最新趋势是构建端到端系统，从多模态传感器直接输出决策轨迹或规划意图，统一建模感知、预测与规划，具备理解能力与泛化能力。代表作：uniad/drivevlm/vadv2
解决问题

新方案在带来新问题的同时，或多或少都在尝试解决上一代感知方案的痛点问题，如：


2d 方案在处理深度预测和遮挡问题时表现不佳；
单目 3d 跨相机区域的后融合效果不佳；
单帧环视 3d 方案受限于瞬时输入使得预测不稳定；
时序环视 3d 方案融合长时序以类“检测+跟踪前融合”的方式提高预测稳定性；
多传感器前融合环视 3d 方案在特征层对齐多传感器特征以实现融合预测；
端到端方案更好地融合感知/预测特征到规划任务以实现更优的 planning 预测。




bev

2021 年 7 月，特斯拉展示了基于 BEV+Transformer（BEVFormer）的自动驾驶感知新范式，取得了经验的效果，也拉开了纯视觉时代的序幕。
对于自动驾驶里面的感知任务而言，最重要的并不光是目标检测与跟踪，目标在极坐标中的表示是人物的难点和重点。对于纯视觉的感知来说，准确地测距是最关键也是最难的问题。对单目测距来说，这是一个病态问题，对于图像中的物体，难以判断它是一个远处的大目标，还是一个近处的小目标。解决这个问题的一个方法是使用双目测距。传统方法是对双目进行严格的标定，利用特征点匹配+对极几何进行计算，但这种方法计算量很大，且严重依赖于标定质量，同时基线的长度限制了测距的范围，所以实际应用有较大的局限性。


IPM 系列

逆透视变换（Inverse Perspective Mapping，IPM）将透视空间的特征反向映射到 BEV 空间，实质是求相机平面与地平面之间的 homography 矩阵。IPM 假设地面是完美的平面，任何路面高度变化和 3D 物体都被忽略在了这一假设。将图像或者特征映射到地平面会导致强烈的视觉失真，阻碍了在环 境中准确定位物体的目标，例如其它车辆和 VRU。因此，IPM 转换的图像或者特征通常用于车道检测或自由空间估计，对于这些场景，平面世界假设通常是合理的。






对于理想的地面车辆而言，相机一旦安装固定了，那么相机相对于地面的姿态是固定的，地面在相机坐标系下的平面方程就是固定的。在标定好相机-地面外参后，像素对应射线已知了，地面方程已知了，它俩的交点就是该像素在相机坐标系下对应的 3D 点。因此，IPM 是相机坐标系下 3D 空间的已知射线与已知平面求交点的问题，通过成像角 θ、相机安装角 α、相机高度 h 反推地面落点坐标。


LSS(Lift,Splat,Shoot)

原文链接：HTTPS://arxiv.org/pdf/2008.05711
显式估计图像的深度信息，对采集到的环视图像进行特征提取，并根据估计出来的离散深度信息，实现图像特征向 BEV 特征的转换，进而完成自动驾驶中的语义分割任务。



LSS 是早期的比较直接的尝试，即先估计每个像素的深度，再通过内外参投影到 bev 空间。只是因为不存在深度标签，这里并没有直接回归深度值，而是对每个像素点预测一系列的离散深度值的概率（文中是 1-50m），概率最大的深度值即为估计结果。



此时我们可以得到深度分布特征α和图像特征 C，将二者做外积，可以得到一个视锥特征（frustum-shaped point cloud），如下图左二所示（因为近大远小的特点）。这一步作者称为 lift。



得到多视角的视锥特征后，可以通过外参将视锥投影到 bev 平面。在 bev 平面下，每个存在高度信息的像素称为体素（voxel），具有无限高度的 voxel 称为 pillar[2]。我们将每个视锥的每个点分配给最近的 pillar，再执行 sum pooling，得到 CxHxW 的 bev 特征。作者采用 cumsum trick 来提升 sum pooling 效率，并把这一过程称为 splat.
有了 bev 特征后，就可以很方便的进行 3D 检测、语义分割、预测和规划等一系列任务，作者把这个过程称为 shoot。LSS 方法可以得到稠密的 bev 特征，缺点是由于每个像素都预测了一系列深度概率值，计算量相对较大。LSS 方法为 bev 感知提供了一种重要的思路。


fastbev

原文链接：HTTPS://arxiv.org/abs/2301.12511





FastBEV 沿用了 m2bev 所采用的投影方案，和上述 Lss 的核心区别是不预测 2d 画面的深度分布，也不会基于深度分布将一份语义特征叉乘出 D 份，也可以理解为假设在相机射线下的每一个像素其在不同深度下的特征都是等值的。这个过程相比于 Lss 的实现看起来更暴力或者难以理解，但如果进一步考虑其原理的话，2d 画面上每一点渲染结果一般只存在于一个具体的位置（少部分情况也可能存在 2d 检测中会遇到的双峰问题，即深度预测可能存在多个峰值），所以理想情况下同一个位置在 Lss 的深度预测下大概率只集中在一个位置（基于显式利用点云信息对深度分支进行监督训练的 bevdepth 也是用一个确切的深度值去辅助学习），这样可以理解 Lss 想做的是对于空间中无占据的区域希望其特征为尽量为 0，对于有物体的区域保留其语义特征，跨视角交叉区域的特征 pooling 融合，最终建模出一个完整的 bev 特征空间。而 m2bev 这种均匀深度投影可以理解为对同一个 2d 位置的每一个深度都采样相同的特征值，跨视角交叉区域的特征同样做 pooling 融合，然后用 3d neck 进一步融合粗采样的 bev 特征，从一些对比实验中也可以看出 3d neck 对 bev feature 的 refine 在不同感知任务下需要的 layer 数量是不一样的，但是 3d neck 本身是不可或缺的，否则精度将明显掉点。
Lss 的经典加速方案有 bevpool 和 bevpool v2，二者都沿用了 lss 的核心思想不变，前者保留了利用深度预测叉乘出待 pooling 的数组这一步，只是对 pooling 本身的实现支持了基于 cuda 的并行计算这样对显存的需求还是没有降低，而 bevpool v2 更近一步，通过构造查找表在线计算不同深度下的特征值，同时保留 cuda 并行 pooling 的特性，这样加速的同时显著降低了显存需求。


FastBEV 则基于深度均匀的假设将加速做到了极致。原始实现同样存在需要首先产生 N 份特征再 sum pooling 的问题，但是我们对比分析了 nuscenes 上不同 camera 之间视角重叠的区域，发现这部分重叠区域占比很小，并且每个 camera 的特征只会在其拍到的 fov 范围内填充有效特征，其余区域都保持为 0，sum pooling 的效果基本等价于将不同 camera 拍到的特征往同一份空白的格子里各自填充一份，只有视角交叉的区域才需要进一步融合。观察到这一点后我们认为这种先独立产生 N 份特征（各自大约只填充 1/N 的有效区域）再 pooling 为 1 份的过程是不必要的，可以直接 N 份特征直接对齐到同一份 volume 特征，对于重叠区域的处理只保留任意一份即可（这里有一些讨论空间，可以只保留任意一份特征，也可以对齐原来的实现 pooling 融合，前者损失了一小部分融合特征，但 nuscenes 实验验证这部分精度损失微乎其微）。再结合查找表优化，构建好查找表后，我们只需要对最终要产生的 voxel 按索引查找一遍其对应采样的 2d 特征按需索取填充即可，这样避免了大量冗余计算。基于上述改进，结合 3d neck 部分 s2c 的技巧以及对模型的量化加速，可以在 cpu 平台和 gpu 平台都实现实时的感知性能，且算子实现简单、跨平台易部署。

BEVDET

BEVdet 是基于 LSS 的自底向上建立 BEV 的方法。如下图所示，先对多视角图像进行特征提取（Image-view Encoder）,再通过基于 LSS 的视角转换（View Transformer）将多视角特征投影到 bev 空间下，再用和第一步类似的 backbone 对 bev 特征进行编码，最后进行目标检测。这种方法虽然在 LSS 这一步存在不少冗余的计算，但好处是得到了显式的 bev 特征，可以做 bev 视角下的特征提取和数据增强，并且可以使用任意的目标检测头。



在真值匹配和后处理上，BEVdet 也偏向传统，使用了 NMS，但提出了 scale-NMS，即对不同类别的目标进行不同尺度的缩放，来做更符合客观场景的目标框过滤，如下图所示。



鉴智的另一篇工作是 BEVerse，加入时序序列构建了感知预测一体的框架。基本思路是对于一个长度为 N 的时序序列，每一帧分别做特征提取和基于 LSS 的视角转换，再经过 BEV 时空编码器融合空间域和时域的多种特征，最后经过多任务解码器做目标检测、建图和运动预测等下游任务。





DETR

LSS 方法进行透视视角到 bev 视角转换是非常直接的，但会带来较高的计算复杂度。而且仅从目标检测这个任务来说，稠密的特征表达其实是非必要的，因为最终目标是得到少量的 target bbox。又因为我们有 transformer 这个大杀器，让自顶向下的稀疏 bev 表示成为可能。DETR 是 vision transformer 用在目标检测的开山之作，首先应用在 2D 检测。它将目标检测任务视为一个图像到集合的问题，即给定一张图像，模型的预测结果是一个包含了所有目标的无序集合。这打破了以 faster-rcnn 为代表的 anchors 和非极大值抑制 NMS 机制，大大简化了目标检测 pipeline。


如上图所示，DETR 的主要框架是首先经过 CNN 提取特征，再通过 transformer encoder 进行全局特征编码，得到 K 和 V 再通过预设的 object queries，与上一步获取的 K 和 V 做 cross-attention，更新 object queries，再经过 FFN(feed forward network)得到目标分类和 bbox 回归结果。这里的 object queries 代表每一个潜在的目标检测框，个数即为最大支持的检测数目，省去了预设大量 anchors 的步骤。作者使用的初始化方式是先进行全 0 初始化，再加上位置编码，也就是只保留位置信息，与检测框的物理意义一致。
DETR 另一个创新之处就是用匈牙利匹配算法（Hungarian algorithm）代替 NMS 机制，在训练阶段计算损失函数之前，先得到一对一的最大匹配，而不是一对多的冗余匹配，在推理阶段也直接得到最终结果，不需要执行 NMS，实现了真正的端到端检测，显著提高了效率。
Deformable DETR 是针对 DETR 计算量大、收敛较慢、难以作用于高分辨率图像等问题，基于可变卷积[9]思想提出了一种可变注意力机制（deformable attention ）:



可变注意力机制避免了原生注意力机制中每个 query 和所有图像特征之间的交互计算，而是引入了参考点（reference points）和采样点（sampling points）,每个 object query 对应一个参考点，代表目标的初始位置，它只和 K 个采样点做交互计算，大大节省了计算量，其中参考点和采样点的位置同样是可学习的，推理的结果不是 bbox 的绝对坐标，而是与参考点坐标的 offset，使推理结果与 decoder attention 直接相关，有利于模型加速收敛。另外，deformable DETR 还使用 cross attention 进行多尺度特征之间的信息交互，不需要 FPN，并用 scale-level embedding 来区分不同尺度，对于小目标的检测效果提升显著。deformable DETR 后续也成为一种重要的范式。



DETR3D 则是即是建立在 DETR 和 deformable DETR 的基础上，将 2D 检测推广到 bev 3D 检测的经典模型。



由于 bev 特征需要从多视角图像特征融合得到，所以需要先对多视角图像提取特征，文中用的是 Resnet+FPN（没有 transformer encoder 模块）。Decoder 模块参照 deformable DETR 的思路，在 bev 空间预设多个 3D 的 object queries，并从 object queries 经线性映射得到 3D 的参考点（reference points)。下一步是 3D 的参考点如何与 2D 的特征做交互，文中利用了内外参的先验信息，将 3D reference points 投影到各个视角的图片上。由于多相机之间存在共视区域和盲区问题，一个参考点可能投影到多个视角，也可能一个视角也投不到，所以作者加了一个二进制的 mask 代表当前视角是否被投影成功。
接下来是做 cross-attention，看代码后发现，DETR3D 的做法与 DETR 和 deformable DETR 都有一些不同，object queries 不是和 DETR 那样与全图交互，也不是和 deformable DETR 那样先从 object queries 预测一些参考点，再预测一些以参考点为基准的采样点，然后和采样点的特征交互，而是直接和 3D 参考点投影的 2D 参考点处的特征交互（经过双线性插值），相当于交互的特征个数=object queries 个数，比 deformable DETR 还要少（每个 object query 预测 K 个采样点，默认是 4 个），应该说是更稀疏的 deformable DETR 了。后面 bbox 推理值和真值的匹配和损失函数的计算和 DETR 是一样的。
比较三者的代码还会发现，DETR 的 transformer 阶段是标准的 attention 计算方式，包含 Q，K，V 的计算，而 deformable DETR 和 DETR3D 的 K 和 V 是合二为一的，与 Q 进行交互。这里可能也是为了节省计算量，或者因为已经进行了特征筛选，不需要再做多维度的特征提取，


petr/streampetr

灵感来自于 bevformer 和 solo fusion，都要缓存非常大的特征帧，端侧部署不友好。









PETR 论文指出，DETR3D 虽然可以得到比较好的性能，但是存在三个问题：
1.bev 空间与多视图之间的信息交互依赖于 3D 参考点估计的准确性，如果估计不准，可能无法投影到有效区域内，无法与 2D 图像进行交互；
2.只进行了 object queries 与 3D 参考点投影的 2D 点的特征之间的信息交互（前文提到），没有学习到全局信息；
3.由于需要采样和投影，DETR3D 的 pipeline 相对复杂，影响推理的效率。
所以，PETR 摒弃了采样和投影，直接计算 2D 多视图对应的 3D 位置编码，并加到 2D 图像特征中，再和 3D 的 object queries 进行交互，直接对 3D object queries 进行更新，大大简化了 pipeline。DETR/DETR3D/PETR 的对比图和 PETR 结构图如下所示：
在 BEVFormer 之后，大家都将 BEV 感知的关注点转移到时序建模上，SOLOFusion 更是展现了长时序建模无与伦比的性能提升。那么现有的时序建模是否还有提升空间呢，为此我们把现有方法划分为两种分别来看：



三种时序融合方式中，Dense BEV 方法在 BEV 空间处理密集特征但计算量大，Perspective 方法通过图像视角 attention 实现高效时序建模但是空间感弱，而 Object-Centric 方法以物体为单位进行跨帧语义传播，只跟踪关键目标的特征并进行传播，稀疏、高效、时序信息保留得好。具备更强的时间一致性和可解释性，适合动态场景理解与跟踪。



StreamPETR 的模型主要分为三大块： 一个 image Encoder、一个 Queue 形式的的内存队列和一个 propagation transformer 组成。这里主要介绍时序融合相关的 Memory Queue 与 propagation transformer：
Memory Queue：Queue 的大小是 ，N 是储存的帧数，K 是储存的 object 的数量。采用先入先出（FIFO）的更新机制，一般根据分类得分选取 TopK 个前景目标的信息进行存储。具体而言，每一个内存空间包含对应 object 的时间间隔 Δt , 语义 embedding Qc ,对象中心点 Qp ,速度 v 和姿态矩阵 E。在实验中我们选取 K = 256 ，相比 BEV 方法节省了近百倍的存储空间。



Propagation Transformer：Propagation Transformer 引入了两个概念， Motion-aware Layer Normalization （MLN）和 Hybrid attention。MLN 实现了隐式的运动补偿，Hybrid attention 则实现 RNN 式的时序交互。
1）MLN MLN 的设计源于 GAN 的，在生成领域，类似的 condition normalization 应用非常广泛。因此我们采用了同样的网络结构设计，将 normalization 层的仿射变换参数变成 dynamic 生成的。动态地去调整每一层的归一化参数，使网络自动学会补偿物体运动带来的变化。
2）Hybrid Attention Hybrid Attention 在这里用于取代原生的 self-attention。首先它起到 self-attention 的作用，对于当前帧的重复框进行抑制。其次，当前帧的 object query 还需要和历史帧 object query 做类似 cross attention 操作，进行时序的交互。
由于 hybrid queries 远小于 cross attention 中 image token 的数量，因此所带来的额外计算量可以忽略不计。此外历史 object query 也会传递到当前帧为当前帧提供更好的初始化（propagate query）。

多模态统一方式对比：lidar2cam 会丢失 lidar 的几何信息，cam2lidar 会丢失画面的语义信息，基于 bev feature 的融合来统一多模态特征是最佳选择。
前融合有几种方法：


首先将雷达点，根据外参和相机内参投影到图像或图像提取的 2D 特征上去采样对应的视觉特征，然后拼接到点云上，后面就可以通过常用的点云 3D 检测算法进行处理，比如 3DSSD[1], PointPillar[2], CenterPoint[3]等，目前 PointPainting[4], PointAugment[5]就属于这类工作；
先对雷达点云进行特征提取，然后将特征或者初始预测值按照外参和相机内参投影到图像或图像提取的 2D 特征上去采样对应特征，然后拼接回来，再接上对应的任务头，目前 MVXNet[6], TransFusion[9]就属于这种类型的工作。

这两种方案在实际环境下会面临以下几种问题：
雷达和相机的外参不准 由于校准问题或车辆运行时颠簸抖动，会造成外参不准，导致点云和图像直接的投影会出现偏差。
相机噪声 比如镜头脏污遮挡，卡帧，甚至是某个相机损坏等, 导致点云投影到图像上找不到对应的特征或得到错误的特征。


雷达噪声 除了脏污遮挡问题；对于一些低反的物体，雷达本身特性导致返回点缺失，我们就在实际场景中发现，在雨天黑色的车辆反射点就极少，如图 2 所示；另外对于某些车型，比如国内新发售的蔚来 ET7，其激光雷达的 FOV 本来就只会覆盖到一个有限的角度。
BEVFusion 的优势，和之前的方法不同的是雷达点云的处理和图像的处理是独立进行的，利用神经网络进行编码，投射到统一的 BEV 空间，然后将二者在 BEV 空间上进行融合。这种情况下雷达和视觉没有了主次依赖，从而能够实现近似后融合的灵活性：单一模态可以独立进行完成任务，当增加多种模态后，性能会大幅提高，但是当某一模态缺失或者产生噪声，不会对整体产生破坏性结果。

occ

除了 bev 感知之外，还有一种感知方案是 2023 年同样由特斯拉号召的 occupancy 感知，它相比于 bev 的区别是从拍平的俯视图特征升维为对 3d 占据的预测，其优点是有更细粒度的感知结果并对通用障碍物有更强的感知能力，但是其真值生产难度大，对算力和算子的需求高，且会输出更 dense 的预测结果，这些使得基于 occupancy 的感知模型上车困难。相比而言，基于 bev 特征的感知任务则更被普遍使用，如基于 dense bev 的障碍物检测、车道线感知、多传感器前融合感知以及端到端模型等。



在一个三维立体空间中，离散的、实例化的 bev 感知可能就不足够了，感知目标是一个 3d 的感知结果，包括车道线，有高度的障碍物。可以去使用一些没有语义的目标。

为避免昂贵的 Occupancy annotations，surround occ 设计了一 种 pipeline，从稀疏的多帧激光雷达点云生成高质量的密集 Occupancy Ground Truth（占用真值标签）。首先，将 dynamic objects 和 static scenes 的多帧点云分别进行融合，然后利用泊松重建（Poisson Reconstruction）算法进 一步填补空洞。最后，利用神经网络和体素化得到稠密的 3D 占用标签。

vadv2--基于概率规划的端到端驾驶模型

从大规模的驾驶演示中学习类似人类的驾驶策略是有希望的，但规划的不确定性和不可定性使其具有挑战性。在这项工作中，为了应对不确定性问题，提出了一种基于概率规划的端到端驾驶模型 VADv2。VADv2 以流方式将多视图图像序列作为输入，将传感器数据转换为环境 tokens 嵌入，输出动作的概率分布，并对一个动作进行采样以控制车辆。只有使用摄像头传感器，VADv2 才能在 CARLA Town05 基准上实现最先进的闭环性能，显著优于所有现有方法。即使没有基于规则的封装，它也能在完全端到端方式稳定运行。闭环演示展示在 HTTPS://hgao-cv.GitHub.io/VADv2 。
如图所示是规划中存在不确定性。环境和动作之间不存在确定性的关系。确定性规划无法对这种不确定性进行建模，尤其是当可行解空间是非凸的。VAD v2 基于概率规划，并从大规模驾驶演示中学习环境条件下的动作概率分布。

Chain-of-Thought




DriveVLM 的整体流程如图 1 所示。一系列图像被大型视觉语言模型（VLM）处理，以执行特定的链式思维（CoT）推理，得出驾驶规划结果。这个大型 VLM 包括一个视觉编码器和一个大型语言模型（LLM）。


首先，视觉编码器生成图像标记；
然后，基于注意力的提取器将这些标记与 LLM 对齐；
最后，LLM 执行 CoT 推理。

CoT 过程可以分为三个模块：场景描述、场景分析和分层规划。








场景描述（Scene Description）

该模块关注于环境感知和关键目标识别，具体包括两部分：


驾驶环境建模（环境描述）：以四元组 天气、时间、道路类型、车道信息天气、时间、道路类型、车道信息天气、时间、道路类型、车道信息 表征影响驾驶行为的重要因素。
关键目标识别：识别对当前驾驶场景最重要的目标（如行人、车辆、障碍物），并提取其图像特征与语义 token，供下游模块使用。

每个目标还进一步分析其：


静态属性 CsC_sCs：如货车、大广告牌等大型静止目标；
动态属性 CmC_mCm：如当前运动状态（速度、方向等）；
特定行为 CbC_bCb：如是否要穿越车道、是否具有优先权等。
场景分析（Scene Analysis）

在识别出环境和关键目标后，进一步推理这些目标对 ego 车的潜在影响与互动关系。重点在于：


将每个关键目标按照静态、动态、行为进行建模；
分析其与 ego 的潜在交互，例如是否会导致减速、让行、刹车；
推理整场景下各要素之间的因果链，为下一步规划奠定基础。
分层规划（Hierarchical Planning）

该模块输出最终的驾驶决策，分为三个阶段：


元动作（Primitive Action）：如“加速”“减速”“变道”等短期驾驶动作。
决策描述（Decision Description）：以自然语言+结构化形式描述执行逻辑，例如“等待行人通过后右转”。
轨迹航点（Waypoint）：最终输出一系列带时间间隔的轨迹点，用于控制模块执行。
DriveVLM-Dual（快慢双系统）

传统视觉语言模型虽然擅长理解复杂场景，但在精确定位目标位置和动态方面存在短板。为此，DriveVLM-Dual 引入了 3D 检测结果，将其与图像中的 2D 关键目标进行匹配，从而识别出“关键目标”。


感知增强：结合 3D 感知信息识别关键目标
匹配成功的关键目标用于辅助轨迹推理（提供空间位置、朝向等信息）；
匹配失败的目标则由视觉语言模型继续分析语义特征，避免遗漏。

这提升了模型在处理关键物体的空间感知与决策能力。


高频轨迹细化：双轨规划机制提升响应速度

由于大模型计算开销大，传统 DriveVLM 生成的轨迹存在延迟。为兼顾精度与实时性，DriveVLM-Dual 采用“慢-快双轨”结构：


先由 DriveVLM 生成粗轨迹（慢轨迹）；
然后在此基础上通过快速规划器进行局部细化，形成最终可执行的快轨迹。

这样既保留了视觉语言模型的语义理解优势，又提升了响应速度，满足车端实时性需求。
