# GitHub第一的 CLAUDE.md

> 作者: @地学万事屋 | 👍 1778 | ⭐ 3317
> 来源: https://www.xiaohongshu.com/explore/69d8f5d500000000210043b1

---

最近看到一个很有意思的 GitHub 仓库，几乎只有一份 CLAUDE.md，却冲到了 Trending 前排。
	
它火的原因很简单。不是功能多，也不是框架大，而是它抓住了 code agent 最容易翻车的 4 个坑。
	
第一，不要替用户乱猜。需求有歧义就先问，不要自己脑补完直接开写。
	
第二，保持简单。50 行能解决的问题，就别写成 200 行，更别提前做一堆没人要的抽象。
	
第三，只做局部修改。不要顺手重构，不要顺手统一风格，不要把一个小任务改成大手术。
	
第四，先定义什么叫“做成了”。修 bug 就先复现再修，加功能就先想清楚验证标准。
	
我看完最大的感受是，真正值钱的不是让 AI 更激进，而是先给它边界。边界对了，速度才有意义。
	
如果你已经在用 Claude Code、Cursor 或其他 agent，这套规则真的值得直接放进项目根目录试一下。
	
你们现在会给 code agent 单独写规范文件吗？
