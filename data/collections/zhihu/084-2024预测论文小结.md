# 2024预测论文小结

> 作者: Model | 来源: https://zhuanlan.zhihu.com/p/21414964379

---

一、前言

对24年看过的一些paper稍微总结了一下

大家开始关注时序一致性这个问题，比如FutureNet-LOF, HPNet，其实工业界对这一块一直非常关注。
现在的方法都注重提出的模块具备“即插即用”特性。
泛化性是一个值得研究的话题，比如在数据集a训练，去数据集b测试，这不仅是在学术界，对工业界也十分重要。对应的文章有UniTraj， sim agent也有论文侧重于这一点
有多篇论文侧重于先基于重建的 方式训一个有场景理解能力的encoder模块，然后再去出未来轨迹，这个系列可以单独做一些小结。
二、24paper
1.【24nips】RealMotion
Paper: Motion Forecasting in Continuous Driving
Code: 无
机构：复旦大学
Motivation

现在的轨迹预测都是基于切分好的场景逐个预测，这其实和实际应用过程中连续帧的预测有些相悖。并且这有几个问题：

历史的预测信息并没有被用于当前帧的预测，比如某个目标在历史时刻没有被遮挡，而当前时刻被遮挡了，这部分目标就会漏掉。（模型没有做到场景的上下文理解）
在训练的时候是逐帧训的，没有考虑时序一致性。

所以本文的侧重点就是实现和应用一致的连续帧预测，作者的做法就是：

先对数据集进行切分，即原先数据集切分好的单个场景会被分为多个连续的子场景。
把历史帧的预测结果和feat存起来当作memory bank. 并分别把轨迹通过坐标系转换到当前帧表示。而feat则借助检测领域的特征变换的MLN做特征对齐。
Framework
Rethinking

如何保证时序一致性对于预测任务非常重要，尤其在工业界，但是对于学术界而言，像av2这类数据集把场景都切碎了，如果想要达到时序一致性就必然需要重新组织数据集，这篇论文确实给了一个比较好的思路，把上次预测的结果再编码到当前帧的预测中来（发散一下，甚至可以进一步将其作为anchor）
2.【24nips】FutureNet-LOF
Paper: FutureNet-LOF: Joint Trajectory Prediction and Lane Occupancy Field Prediction with Future Context Encoding
Code: 无
机构：北大
Motivation
现有的预测工作没有关注未来轨迹的编码，于是本文提出了编码未来轨迹且进行交互的思路。（区别于MTR那种把中间预测的未来轨迹重新编码进来，该方案是迭代的预测未来，每次迭代的终点都是作为下次迭代的起点）
现有的工作大部分都集中在预测每个agent的独立未来（ marginal模型），但在自驾领域需要在复杂环境中的对周围agent进行联合预测（joint预测）。本文 提出了车道占用场(LOF)，就是说每个agent在未来每一时刻可能占据的车道线。LOF可以同时获取道路参与者在未来时空的联合概率分布。（但实验部分在多智能体预测上并没有超越QCNet，个人这个模块是否真正有效存疑）
Framework
这个框架图有些乱，不过论文的附录有详细的步骤。（建议看原论文）
Rethinking
车道占用场的思路非常有意思，在某一帧下如果某个车道被占用了，那么其它agent的轨迹就不应该在这一点进行预测了，但似乎这篇论文并没有完全验证这个模块的有效性？
论文中会对每一帧每一个点都建立局部坐标系，即将其它agent都转换到该帧的局部坐标系下表示，这个计算量想想就恐怖，事实上该方法用8*a100才训得起来，可见计算量得有多大。
另一方面，逐段预测的方式这个思路和下面的SmartRefine比较相似。
3.【24nips】DeMo
Paper: DeMo: Decoupling Motion Forecasting into Directional Intentions and Dynamic States
Code: https://github.com/fudan-zvg/DeMo
机构：复旦
Motivation

主流方法采用单查询-单轨迹范式，其中每个查询对应于预测多模态轨迹的唯一轨迹。 这里其实涉及到两个概念，模态和轨迹。于是本文将二者解耦开，分为模态query和状态query，思路和PiH特别像。
第二就是首次将manba框架引入到了轨迹预测

Framework
Rethinking
这里的模态和轨迹是同时预测的，有两个分支，且会辅助监督，然后再会拼起来。
先方向预测，再速度预测，从直观上是合理的。肯定是得先决定去哪儿（方向），再来决定应该怎么去（加速，减速等等）
4.【24iclr】SEPT
Paper: SEPT: TOWARDS EFFICIENT SCENE REPRESENTATIONLEARNING FOR MOTION PREDICTION
Code: 无
机构：清华
Motivation

受预训练大型语言模型启发，本文侧重于轨迹预测的预训练，主要就是encoding部分。作者认为目前的轨迹预测模型中的encoder模块主要是agent-ageng交互，map-map交互，agent-map交互，这类方式不仅计算量大而且也并没有做到真正的场景理解，于是作者提出了SEPT，agent和map各自编码之后直接进行交互，最后接decoder模块出轨迹。本文的整个框架非常简单，但从encoder预训练的角度来提升预测性能非常有意思，整个网络参数只有QCNet的40%，但性能还更强，在av2上表现SOTA。

Framework

将上述框架拆解开，大概就是三部分：

MTM(Marked Trajectory Modeling)：利用一个可学习的mask来随机去掉轨迹的部分帧，然后再把整条轨迹重建出来
MRM(Masked Road Modeling): 与轨迹重建模块一样，这里是需要重建车道线
TP(Tail Prediction): 将一条轨迹分为尾部和头部，基于尾部预测头部（可以理解为一个简单的短时预测）


将上述三部分训好之后，再联合起来训。

Rethinking

类似的方法包括Traj-MAE和Forecast-MAE（这两篇方法还没来得及看）
总结下来，可以理解为先短时预测，然后把模型训好，具备短时预测的能力，然后再对更长的未来进行预测，将一个完整的网络分成多个子网络分别进行训练，模型的参数来也不需要很大，论文说只需要一块3090就能训起来。
5.【24cvpr】HPNet
Paper: HPNet: Dynamic Trajectory Forecasting with Historical Prediction Attention
Code: https://github.com/XiaolongTang23/HPNet
机构：中科院
Motivation

最近的主流方法遵循静态范式，通过使用固定的历史帧持续时间来预测未来轨迹。这些方法即使在相邻的时间步也独立地进行预测，这导致了潜在的不稳定和时间不一致。 由于连续的时间步长具有很大程度上重叠的历史帧，因此它们的预测应该具有内在的相关性，例如重叠的预测轨迹应该是一致的，或者根据道路情况不同但具有相同的运动目标。基于这一点，本文主要探索时序一致性的预测，做法是把历史帧的预测轨迹作为当前帧预测的输入。具体来说，设计了一个历史预测注意力模块，用于自动编码连续预测之间的动态关系。

Framework
假如当前是t时刻，包含I_1的历史帧，要预测未来的t_f帧，那么当前时刻做完交互后的特征会与上一时刻交互后的特征再交互（而上一时刻也同样基于那一时刻包含历史I_1帧的信息），即当前时刻的特征与上一时刻的特征交互完了之后，理论上也包含了t_l1_1那一帧的信息，即这种方式包含了更久远的历史信息。
Rethinking
这篇论文思路和RealMotion比较像，都是想把历史帧的信息用上，但二者又有区别
RealMotion：把历史帧预测的未来轨迹，通过某些操作变换到当前帧下表示，然后再进行编码与当前帧的信息交互，这个侧重点在于把历史的预测信息加到当前帧
HPNet：而本文的思路更侧重于把更久远的特征加进来，即把历史每一时刻都编码好的feat(准备用于对未来的轨迹进行预测的最终的feat，该feat已经聚合了历史时刻的信息)与当前时刻的feat做交互，而每一时刻的feat又包含了历史n时刻的信息，这样就套娃上了
水论文的点：把二者一结合。。。。
6.【24cvpr】MoST
Paper: MoST: Multi-modality Scene Tokenization for Motion Prediction
Code:
机构：Waymo
Motivation

现在的预测模型直接使用感知的输出当做输入，感知的输出是高阶信息(框层面)，而原始的道路信息则被过滤掉了，比如道路上的锥桶、建筑物啥的，这些物体是无法用检测模型给出具体的框的，另一方面，对于行人而言，框层面的信息无法很好的给出行人的朝向（尽管有朝向信息但并不一定准），原始的图像信息可以更好的描述，基于上述问题，这样对预测模型而言会很大程度上收到感知精度的影响，所以作者认为需要拿到原始的信息。
而目前的端到端方法虽然能够拿到原始的图像或点云信息，但是对于模型的学习难度太大，因为图像的像素和点云包含的信息量太多了，想让模型直接学非常困难，且这种方式缺乏可解释性。
所以本文想结合这两种方法的优点，即既用框也用原始信息。

Framework

输入包含图像和点云，先分别用各自的backbone进行特征提取，然后利用内外参将点云投到图像上做特征融合，然后会使用聚类的方法将场景中的原始划分为：

地面元素：使用聚类的方式获取对应的最小的bbox来表示
agent元素：通过bbox 获取对应的点云
开集目标元素：agent之外的元素，训练数据之外的新类别交通参与者和障碍物，会获取对应的最小的bbox来表示。为何保证多帧的障碍物在时序上能够对应，这里边会有一个小的跟踪模块。

上述三类目标有分别对应的框信息（坐标），也有框所对应的点云和图像信息，并且这些信息是多帧的，然后通过如下的方式做特征聚合，图中的 $$F_{pts}， P_{xyz}，B$$依次表示为原始图像信息，点云信息和框的信息

这三类信息分别编码之后再进行时序上的融合，其中点云的两类 $$ P_{xyz}，B$$会聚合成 $$F_{geo}$$，称之为几何特征，然后与图像特征以及引入一个可学习的向量做最后的时序融合，具体如下

Rethinking

引入原始的点云和图像特征肯定是未来预测任务所必须的，就像论文中所说，完全端到端而不需要框的信息输入是非常困难的，所以大概率后续的形态就是原始特征和框信息共存。

7.【24eccv】UniTraj
Paper: UniTraj: A Unified Framework for Scalable Vehicle Trajectory Prediction
Code: https://github.com/vita-epfl/UniTraj
机构：洛桑联邦理工学院
Motivation

一方面目前各个方法都只是在部分数据集上刷榜，而且泛化性差。另一方面，各大数据集差异较大，评测方法不一。所以本文意在对这些问题做到统一：

统一了各大数据集的格式，包括argoverse2, nuScenes和waymo
对目前主流的一些方法做到了继承，比如MTR
对各大数据集采用的评测指标做到了统一，如waymo采用的是map，而av2采用的是brier min FDE,能够实验在同一数据集都对使用这些指标进行评估。并且进一步对轨迹分类评估，如执行、转弯等类别分别评测
做了很多的泛化性以及data scaling的实验，探究了同一模型在不同数据集不同城市之间的泛化性，以及同一模型在不同数据量训练下的表现

Framework
Rethinking

非常好的一个工作！！！我们之前的MCTrack是在跟踪领域做了一个大一统，把各个数据集的格式统一了，而这篇文章则是在预测领域做到了大一统。同一模型，在数据集a上训，去数据集b上测，以及在同一数据集下根据不同数据量的训练来评测，非常有意思！另外在实验部分，作者对评测场景进行了分类，按照直行、静止、转弯等类别分别评测，这一点和泛化性对工业界也是很重要。


将轨迹预测模型适应新的数据集而不删除先前的知识，称为灾难性遗忘。作者尝试使用AutoBot在waymo上先训，然后再基于av2上finetune，这样能够提高模型在av2上的性能但是会降低在waymo上的性能。反过来也是，在av2上先训好当做预训练，然后在waymo上进行finetune，可以增强模型在waymo上的表现而降低在ag2的性能

7.【24cvpr】SmartRefine
Paper: SmartRefine: A Scenario-Adaptive Refinement Framework for Efficient Motion Prediction
Code: https://github.com/opendilab/SmartRefine/
机构：商汤，港中文
Motivation

最近的预测工作都是两阶段的方式，先预测粗糙的轨迹然后再进行细化调整，这种方式存在两个问题，一是计算量大，二是性能提升不明显。所以就如何高效的refine轨迹，作者通过引入质量分数来动态调整轨迹需要被refine的次数。

Framework
Adaptive Anchor/Context Selection：以前的方法都是固定范围来与周围的环境进行交互，这种方式尽管简单，但不一定是最优的，因为不同的数据集可能需要交互的范围不一样。所以本文搞了一个动态的交互范围，从两个方面出发：

每次迭代得到的轨迹会更精细，那么其需要关注的范围就应该越小（上图中的左下图，第1次迭代的时候，虚线圈很大，第I次迭代的时候，虚线圈就变小了）
速度大的目标其关注的范围应该更大
Anchor-Centric Context Encoding：现有的方法都是以agent当前帧建立的坐标系，这种方式在于强调当前时刻周围的环境信息，而在refine过程中，更应该强调未来时刻周围的环境（这一点不太理解，通过一个坐标系变换就能实现？），所以本文提出了以anchor为中心的编码方式
Recurrent and Multi-Iteration Refinement：作者认为以前的refine是一次性把特征都融合起来多次refine，这种方式会存在累计误差，所以作者采样将一条轨迹分成多段，每段依次refine，可以认为前一段refine好了再refine后面一段的轨迹
Adaptive Number of Refinement Iterations：每次refine会出轨迹点和对质量分数，如果质量分数大于所设定的阈值则refine结束，或者如果质量分数一直很低，但是迭代次数达到阈值时也会终止。
质量分数：每次refine的轨迹和gt会有个误差，误差最大的那一次称之为 $$d_{max}$$，而最小的为 $$d_{min} $$，如果某次的 $$d_i $$通过如下公式得到的质量分数大于阈值的话，就迭代终止。
Rethinking

分段依次refine轨迹从某种程度上可以理解为分段自回归，只有这一段refine好了，再去refine下一段，思路和FuterNet-LOF 一致。

9.【24cvpr】FLN
Paper: Adapting to Length Shift: FlexiLength Network for Trajectory Prediction
Code:
机构：美国东北大学
Motivation

现有的模型都是固定轨迹历史长度作为输入，这就导致在使用不同历史长度测试时其性能大幅度下降，作者这种现象为Observation Length Shift，具体包含如下两个问题：

位置编码的偏差（Positional Encoding Deviation）：对于 Sinusoidal位置编码，会存在基于时序长度来获取相对时刻的关系，那么对于同一条轨迹而言，同一位置在不同长度下的位置编码是不一样的
规范化的偏差（Normalization Shift）：在长度H的历史数据上训，模型的 Layer Normalization 学会的是历史长度H的均值和方差，但当使用另一个长度的数据测时，其数据的均值和方差是不一样的

所以本文为了解决该问题，提出了FlexiLength Network (FLN），即会使用各种不同观测长度的数据作为输入

Framework

首先会将历史H长度的滑窗或者截断的方式分成长、短、中等三类轨迹，然后同时进行编码，包括时空交互等（在做attention的时候会各自用Sinusoidal位置编码），这里会共享权重，然后过各自的LN层，最后贡献decoder模块出各自的预测轨迹，但这里只会对长的历史轨迹那个分支预测的轨迹与GT监督，剩下的中等和短的预测只会和长的预测算KL散度

10【24cvpr】T4P
Paper: T4P: Test-Time Training of Trajectory Prediction via Masked Autoencoder and Actor-specific Token Memory
Code: https://github.com/daeheepark/T4P
机构：
Motivation
现有的预测方法基本都存在欠拟合或者过拟合的问题，因为他们只优化decoder的最后一层（没太懂），为了解决该问题，作者提出了 masked autoencoder 的模块来更好的编码（但这一点似乎很多工作都在做，比如SEPT, ForecastMAE 等待）
引入了actor-specific token memory 并采用Test Time Training（TTT）的训练方式，主要解决测试数据和训练数据存在差异时能够具有泛化性.
Framework
Offline training: 核心就是 重建，类似于SEPT, ForecastMAE ，对轨迹和车道线先随机mask，然后能够补全，会有一个重建的loss来监督，目的就是学一个能够有场景理解的编码模块。这个过程中同时与预测未来轨迹
Test-time training： 在测试数据集中借助历史帧的gt来更新模型，即当前时刻是没有gt的，但是历史那一时刻到当前时刻的数据可以作为历史那一时刻下的gt。这里主要是要训一个Actor-specific token memory模块（这一块没太看懂）
Rethinking
这篇文章没太看懂，但是 利用 重建 的思路来训一个更好的encoder模块似乎是大家比较关注的一个问题，比如SPET, ForecastMAE等工作，这一块需要系统总结一下看看大家都是怎么做的。
